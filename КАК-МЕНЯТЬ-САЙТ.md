# Как менять сайт хора

Инструкция для того, кто ведёт сайт. Программировать не нужно.

---

## Главное правило

Весь текст сайта лежит в одном файле — `src/content.json`.
Больше ничего трогать не нужно.

Меняйте только то, что стоит **внутри кавычек**. Сами кавычки, запятые,
двоеточия и фигурные скобки оставляйте на месте — сайт собран так, что без
них он перестанет обновляться.

Строки, которые начинаются с `_подсказка`, на сайте не видны. Это заметки
для вас, их можно не трогать.

---

## Как изменить текст, не устанавливая ничего на компьютер

1. Откройте репозиторий на сайте **github.com**.
2. Зайдите в папку `src` и нажмите на файл `content.json`.
3. Нажмите на карандаш в правом верхнем углу — файл станет редактируемым.
4. Измените нужный текст.
5. Пролистайте вниз, нажмите зелёную кнопку **Commit changes**.

Через две-три минуты сайт обновится сам. Проверить можно, открыв адрес сайта
и обновив страницу.

Если что-то сломается, GitHub покажет красный крестик рядом с вашим
изменением. Это не страшно: нажмите на историю изменений и верните
предыдущую версию.

## Частые задачи

### Поменять расписание репетиций

Найдите блок `"репетиции"`, внутри него `"расписание"`:

```
"расписание": [
  { "день": "Вторник", "время": "19:00 — 21:00" },
  { "день": "Четверг", "время": "19:00 — 21:00" }
],
```

Чтобы добавить третий день, скопируйте строку целиком, вставьте её ниже и
не забудьте запятую в конце предыдущей строки. У последней строки в списке
запятой быть не должно.

### Добавить анонс концерта

Блок `"анонсы"`, внутри `"события"`. Скопируйте существующее событие целиком
— от `{` до `}` — и заполните своими данными.

Поле `"ссылка"` можно оставить пустым: `""`. Тогда кнопка «Подробнее» просто
не появится.

### Убрать блок с сайта

Если анонсов или достижений пока нет, сделайте список пустым:

```
"события": []
```

Блок исчезнет со страницы целиком. Когда появится, что показать, — вернёте.

### Добавить фотографии

1. Положите файлы в папку `public/images`. На github.com это делается так:
   зайдите в папку, нажмите **Add file** → **Upload files**.
2. В блоке `"галерея"` перечислите их:

```
"снимки": [
  { "файл": "/images/concert-may.jpg", "подпись": "Майский концерт" }
]
```

Имя файла в `content.json` должно совпадать с именем загруженного файла
буква в букву, включая расширение.

Горизонтальные снимки смотрятся лучше вертикальных. Размер файла желательно
до 500 КБ — иначе страница будет долго открываться на телефоне.

### Заменить фотографию на обложке

Загрузите свой снимок в `public/images` и впишите его имя в блок
`"обложка"`, поле `"фото"`.

## Чего делать не нужно

- Не переименовывайте названия полей — то, что стоит слева от двоеточия.
  Сайт ищет их по именам и без них не соберётся.
- Не удаляйте квадратные `[ ]` и фигурные `{ }` скобки.
- Не вставляйте текст из Word — он приносит с собой невидимые символы,
  которые ломают файл. Если копируете откуда-то, вставляйте через «Блокнот».
- **Правьте `content.json` прямо на github.com, а не в «Блокноте».** Блокнот
  при сохранении дописывает в начало файла невидимую служебную метку, из-за
  которой сборка падает с ошибкой вида `is not valid JSON`. На экране при
  этом всё выглядит нормально — найти причину без подсказки невозможно.
- Не пишите пароли ни в один файл проекта, кроме `SECRETS.local.md`.
  Репозиторий публичный, всё остальное в нём видно любому человеку
  в интернете.

---

## Если сломалось

Ничего непоправимого случиться не может: GitHub хранит все версии файла.

1. Откройте `content.json` на github.com.
2. Нажмите **History** — это список всех изменений.
3. Найдите версию, когда всё работало, откройте её и скопируйте содержимое
   обратно в файл.

Чаще всего причина — лишняя или пропущенная запятая.
