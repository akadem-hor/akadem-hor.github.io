## 1. Цель

Сайт-визитка любительского академического хора «Свои голоса», Екатеринбург.

Две задачи:

1. **Поиск.** Чтобы хор находили в Яндексе по запросам «академический хор
   Екатеринбург», «любительский хор Екатеринбург», «набор в хор
   Екатеринбург», «хор для взрослых Екатеринбург». Сейчас по этим запросам
   в городе не находится почти ничего — это наша основная возможность.

   **Запрос «куда пойти петь взрослому» сознательно убран из целей
   24.09.2026.** Его задают люди без всякой подготовки, а хор академический:
   нужны слух и хотя бы начальные знания нот, большинство участников
   окончили музыкальную школу, некоторые пели в профессиональных хорах.
   Такой посетитель пришёл бы, получил отказ и ушёл расстроенным. Трафик,
   который не может конвертироваться, вредит дважды: тратит время хора на
   отказы и портит поведенческие показатели сайта.
2. **Первый визит.** Чтобы человек за пару минут понял, подходит ли ему хор,
   и дошёл до репетиции.

   **Уточнено 24.09.2026.** Заявок у хора нет и не было. Люди приходят по
   знакомству: кто-то позвал, рассказал по дороге, что за хор, успокоил,
   познакомил с хормейстером. Дальше хормейстер объясняет остальное прямо
   на занятии.

   Но сайт делается ради поиска, а из поиска приходит человек **без
   приведшего**. Рядом нет никого, кто объяснит, как себя вести.
   **Отсюда задача страницы: заменить собой реферала.** Не собрать анкету,
   а рассказать то, что обычно говорят по дороге на репетицию — что будет
   происходить, к кому подойти, не выгонят ли.

   Это меняет и то, чем измеряется успех: не числом заявок, а тем, доходит
   ли незнакомый человек до двери.

**Аудитория:** взрослые 30–70 лет, значительная часть заходит с телефона.

### Условия GitHub Pages

Бесплатно, без карты, SSL включается галочкой. Обязательное условие —
**репозиторий должен быть публичным**, иначе Pages требует платный тариф.
Отсюда правило про пароли в разделе 7.

**Принятый риск:** GitHub — иностранная площадка. Сегодня из России
открывается, завтра гарантий нет. Запасной аэродром — Яндекс Object Storage.

### Запасные варианты хостинга

- **Яндекс Object Storage** — 1 ГБ хранения, 10 000 операций записи и
  100 000 операций чтения в месяц бесплатно. Наш сайт весит 20–30 МБ, лимита
  чтений хватает примерно на 5000 посещений в месяц. Нужен платёжный аккаунт
  с привязанной картой, списаний в пределах лимитов не будет.
- **Beget или Timeweb, платный тариф** — от 420 ₽/мес. Бесплатных тарифов у
  них нет, только тестовый период 30 дней.

## 3. Домен

**Решение от 18.09.2026: домен не покупаем, работаем на `*.github.io`.**

Проверка 18.09.2026: у `svoigolosa.ru`, `svoi-golosa.ru`, `svoigolosa-ekb.ru`
и `hor-svoigolosa.ru` нет делегированных NS-серверов. Скорее всего свободны,
но это не доказательство — точный ответ даёт whois.

**Риск, принятый осознанно.** Свой домен нужен не для красоты адреса, а для
обратимости: пока адрес наш, хостинг можно менять без потерь. Без домена
любой переезд — а он вероятен, см. риск GitHub выше — обнуляет накопленные
позиции в поиске, и набор в хор через поиск начинается заново.
Цена вопроса — около 250 ₽/год.

**К этому вопросу стоит вернуться до того, как сайт наберёт позиции в
Яндексе** — примерно через два-три месяца после публикации. Чем позже
переезд, тем дороже он обходится.

| Поле | Значение |
|------|----------|
| Рабочий адрес | https://akadem-hor.github.io |
| Организация на GitHub | `akadem-hor` |
| Репозиторий | `akadem-hor/akadem-hor.github.io`, публичный |
| Свой домен | `akadem-hor.ru` — **выбран, покупка готовится** |
| Регистратор | reg.ru |
| На кого оформлен | _заполнить при покупке_ |
| Чья карта платит за продление | _заполнить при покупке_ |
| Автопродление включено | _заполнить при покупке_ |
| Дата следующего продления | _заполнить при покупке_ |

### Почему домен нейтральный

**Название хора ещё не выбрано.** «Свои голоса» — рабочий вариант, он может
измениться.

Отсюда решение брать домен, не завязанный на название. Когда имя утвердят,
менять придётся только три поля в `content.json` — заголовок, название на
обложке и подпись в контактах. Адрес сайта останется прежним, накопленные
позиции в поиске не пострадают.

Если бы домен назывался по хору, смена названия потянула бы за собой смену
домена, то есть полный сброс поисковой истории. Нейтральный адрес отвязывает
сайт от нерешённого вопроса.

По той же причине 25.09.2026 организация на GitHub переименована из
`svoi-golosa` в `akadem-hor`: чтобы имена не расходились.

### Кто владеет доменом

**Решено 25.09.2026: домен покупает руководитель хора, на своё имя.**
Он остаётся с хором дольше всех, поэтому риск потерять домен вместе
с человеком здесь наименьший.

Домен оформляется на паспорт конкретного человека. Не на хор.

Это та же развилка, что была с GitHub, где мы завели организацию отдельно от
личного аккаунта. Но последствия жёстче: организацию можно перезавести за
десять минут, а домен придётся выкупать, перерегистрировать или потерять
вместе с накопленными позициями в поиске.

**Сценарий, ради которого это записано.** Человек купил домен, через год ушёл
из хора или перестал отвечать. Автопродление привязано к его карте, карта
истекла — домен отключился, сайт пропал, и сделать никто ничего не может.

Поэтому покупать должен тот, кто останется с хором надолго: хормейстер или
руководитель, а не тот, кому удобнее прямо сейчас. Как решится — вписать
в таблицу выше, а доступы к reg.ru занести в `SECRETS.local.md`.

### Настройка DNS, если покупает не тот, кто настраивает

Пароль от reg.ru передавать не нужно: к аккаунту привязаны паспортные данные
и карта. Записи прописываются один раз, поэтому достаточно отправить владельцу
таблицу из пяти строк.

Записи для GitHub Pages (четыре A на `@` и одна CNAME на `www`):

```
A      @      185.199.108.153
A      @      185.199.109.153
A      @      185.199.110.153
A      @      185.199.111.153
CNAME  www    akadem-hor.github.io.
```

Точка в конце CNAME обязательна. Прежние записи A и CNAME, которые reg.ru
создаёт сам под страницу-заглушку, нужно удалить — иначе сертификат HTTPS
не выпустится. Записи NS, SOA и MX не трогать.

## 4а. Две рабочие машины

Проект ведётся с двух компьютеров, и возможности у них разные.

### Домашний компьютер — сборка работает

Проверено 19.09.2026. Node.js 24.13, npm 11.6.2, права администратора есть,
прокси нет. `npm install` проходит, `npm run build` собирает сайт за полторы
секунды.

```
npm install      # один раз
npm run dev      # посмотреть в браузере, обычно http://localhost:4321
npm run build    # проверить, что сборка не падает
```

**Это основная машина для правок кода.** Ошибка видна сразу, а не через три
минуты в журнале GitHub.

### Рабочий компьютер — сборка невозможна

Выяснено 18.09.2026.

- **Нет прав администратора.** Установщик Node.js через MSI не проходит.
  Обходится распаковкой портативного архива в папку пользователя:
  `%LOCALAPPDATA%\nodejs-portable`. Node.js 24.21 и npm 11.19 так работают.
- **Корпоративный прокси `ext-proxy.kontur:8080` закрывает реестр npm.**
  `npm install` возвращает 403, имя `registry.npmjs.org` не разрешается
  напрямую. Установить зависимости на этой машине нельзя.

Следствие: с рабочей машины правка проверяется только после отправки в
репозиторий, а текст ошибки приходится смотреть в журнале сборки на
github.com, вкладка Actions.

Git работает на обеих машинах: на рабочей он установлен в папку пользователя,
доступ к GitHub сохранён в диспетчере учётных данных Windows.

## 5. Правила вёрстки и дизайна

Продиктованы аудиторией 30–70 лет, преимущественно с телефона:

- Базовый размер шрифта — не меньше 18px, заголовки крупные
- Высокий контраст текста и фона, не ниже уровня AA
- Кнопки и ссылки — крупные зоны нажатия, не меньше 44×44px
- Минимум анимации. Никаких появлений при прокрутке, каруселей, эффектов
- Мобильная вёрстка — основная, десктоп подстраивается под неё
- Никаких модальных окон, всплывающих подписок, скрытых меню

## 7. Доступы и пароли

**Паролей в этом файле нет и быть не должно.**

Все логины и пароли — в файле `SECRETS.local.md` рядом с этим. Он закрыт
через `.gitignore` и никогда не попадёт на GitHub.

Причина: сайт размещается на GitHub Pages, а бесплатный Pages работает
только с публичным репозиторием. Всё, что лежит в репозитории, видно всему
интернету. Поэтому правило жёсткое — **никаких паролей в файлах проекта,
кроме `SECRETS.local.md`.**

Если `SECRETS.local.md` потеряется, восстановить пароли будет неоткуда.
Имеет смысл держать копию в менеджере паролей.
